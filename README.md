# Spiti

평면도 구조를 3D 집 내부로 세우고, 실제 치수의 가구를 끌어다 놓아 배치해 보는 웹 앱입니다. 평형대별 구조 프리셋 41장이나 내보낸 프로젝트 파일로 시작하고, 평면도 보기에서 방 경계를 끌어 우리 집 크기에 맞춘 뒤 가구를 배치할 수 있습니다. 제품 정의는 [PROJECT.md](PROJECT.md)에 있습니다.

## 실행

```bash
cd web
npm install
npm run dev      # http://localhost:5173 (로컬 개발 서버)
npm test         # 평면도 해석·충돌 계산·되돌리기·배치 파일 단위 테스트
npm run build    # 타입 검사 + 정적 빌드 (web/dist)
```

Node.js 22 이상을 권장합니다.

## 빌드와 정적 서빙

`npm run build`는 타입 검사 후 `web/dist`에 정적 번들을 만듭니다. 저장소 루트의 `Dockerfile`은 Node로 번들을 빌드하고 nginx로 서빙하는 이미지를 만듭니다.

```bash
docker build -t spiti .
docker run --rm -p 8080:80 spiti   # http://localhost:8080
```

번들은 상대 경로로 만들어지므로 어떤 하위 경로에 올려도 열립니다.

## 화면

- **시작 화면**: **프로젝트 파일 열기**와 10·20·30·40평대 구조 프리셋 41장을 보여 줍니다. 상단 막대의 **구조** 버튼으로 언제든 다시 열 수 있습니다.
- **왼쪽 3D 화면**: 벽, 문, 바닥, 붙박이 싱크대를 평면도 치수(cm) 그대로 세웁니다. 상단 막대에서 3D/평면도 보기, 벽 높이(240/100), 와이어프레임, 방 이름 표시, 가구 라벨 표시를 바꿀 수 있습니다.
- **오른쪽 가구 목록**: 카드를 3D 화면으로 끌어다 놓으면 배치됩니다. 카드를 누르기만 하면 화면 가운데에 놓입니다. 끄는 중에 `R`을 누르면 미리 돌릴 수 있습니다.
- **선택한 가구**: 위쪽 패널에서 이름, 가로·깊이·높이, 회전 각도, 색을 바꾸고 복제·삭제할 수 있습니다.
- **가구 라벨**: 배치한 가구마다 이름 라벨이 붙습니다. 선택한 가구의 패널에서 **라벨 메모**(예: 분해 후 이동, 새로 구매)를 적으면 이름 아래에 한 줄로 함께 보입니다. 평면도 보기에서 가구를 고르지 않은 상태로 화면을 캡처하면, 어느 가구가 어느 방 어디에 들어가는지 이삿짐센터에 그대로 전달할 수 있습니다.

### 구조 프리셋

시작 화면에서 10·20·30·40평대 프리셋 41장을 고를 수 있습니다. 10평대는 아파트 4·빌라 4·단독주택 3, 나머지 평형대는 아파트 4·빌라 3·단독주택 3으로 묶여 있습니다. 프리셋은 열·행 격자 파라미터로 만들어지므로 방 경계를 움직이면 방·벽·문·창·싱크대가 함께 다시 계산됩니다.

프리셋을 고르면 그 구조의 배치를 새로 시작합니다. 이전 구조의 배치는 그 구조의 localStorage 키에 남아 있어 나중에 다시 열 수 있습니다.

### 평면도에서 방 크기 조절

평면도 보기로 바꾸면 프리셋 구조의 안쪽 열·행 경계와 오른쪽·아래 바깥 경계에 파란 손잡이가 나타납니다.

| 조작 | 동작 |
|---|---|
| 안쪽 손잡이 드래그 | 양옆 칸의 크기를 맞바꿔 방 경계를 이동 (전체 폭·깊이는 그대로) |
| 오른쪽·아래 손잡이 드래그 | 바깥 경계를 움직여 전체 폭·깊이 변경 |
| `Shift` + 드래그 | 5cm 대신 1cm 단위로 미세 조정 |
| **구조 기본값으로** | 끌어서 바꾼 구조를 프리셋의 처음 격자로 복원 |

방은 종류별 최소 크기(욕실 120×150, 침실 180×210, 거실 240×240cm) 아래로 줄어들지 않고, 전체 크기는 300~1600cm 안에서 움직입니다. 구조를 바꿔도 배치한 가구는 유지되며, 새 외곽 밖으로 나간 가구 중심은 안쪽 5cm로 당겨집니다.

### 가구 조작

| 조작 | 동작 |
|---|---|
| 가구 드래그 | 이동 (벽이나 다른 가구 면에 10cm 이내로 다가가면 딱 붙음) |
| 바닥의 파란 링 드래그 | 15° 단위 회전 |
| `Shift` + 드래그 | 벽 붙임 해제 / 1° 단위 자유 회전 |
| `R` / `Shift+R` | 시계 / 반시계 90° 회전 |
| `Q` / `E` | 반시계 / 시계 15° 회전 |
| 방향키 (`Shift`) | 화면 기준 1cm (10cm) 이동 |
| `Ctrl+D`, `Delete` | 복제, 삭제 |
| `Ctrl+Z`, `Ctrl+Shift+Z` | 되돌리기, 다시 실행 |

벽, 싱크대, 다른 가구와 겹친 가구는 빨간색으로 표시합니다. 러그는 겹쳐도 되고, 의자는 식탁과 책상 밑으로 들어가도 됩니다. 배치 상태는 브라우저 localStorage에 저장됩니다.

### 프로젝트 내보내기와 가져오기

상단 막대의 **내보내기**를 누르면 지금 평면도(구조)와 배치가 `spiti-project-<평면도 id>-<YYYYMMDD-HHmm>.json` 파일로 함께 내려받아집니다. **가져오기**로 그 파일을 고르면 구조와 배치를 함께 열며, 다른 구조에서 만든 파일이면 한 번 확인합니다. 평면도를 읽지 못하거나 버전이 더 높으면 이유를 알려 주고 파일을 열지 않습니다. 파일 형식 이름 `spiti-layout`은 그대로이고 버전은 2입니다.

```json
{
  "format": "spiti-layout",
  "version": 2,
  "plan": {
    "version": 1,
    "id": "preset-villa-10-two",
    "name": "빌라 투룸 · 복도형",
    "unit": "cm",
    "rooms": [],
    "walls": [],
    "openings": [],
    "fixtures": [],
    "notes": []
  },
  "exportedAt": "2026-10-20T10:34:00.000Z",
  "items": [
    { "uid": "…", "typeId": "bed-queen", "name": "퀸 침대", "x": 470, "z": 200, "rot": 90, "w": 160, "d": 210, "h": 90, "color": "#9fb4c7" }
  ],
  "preset": {
    "kind": "villa-10-two",
    "rooms": 5,
    "baths": 1,
    "width": 630,
    "depth": 720,
    "columns": [200, 160, 270],
    "rows": [170, 220, 330],
    "cells": []
  }
}
```

- `plan`은 평면도 전체입니다. 좌표는 cm이고 `plan.id`·`plan.name`으로 어떤 구조인지 알 수 있습니다.
- `preset`은 프리셋 구조일 때만 들어갑니다. 가져올 때 이 격자 파라미터로 평면도를 다시 만들기 때문에, 파일을 다시 열어도 경계 드래그로 크기를 계속 조절할 수 있습니다. 프리셋이 아닌 평면도 파일에는 없습니다.
- `x`, `z`는 가구 바닥 중심의 평면도 좌표(cm)이고, `rot`은 위에서 볼 때 반시계 방향 각도입니다.
- 파일의 구조가 지금 화면과 다르면 구조를 바꿀지 묻고, 바꾸면 구조와 배치를 함께 엽니다. 같은 구조만 다르면 배치만 바꾸며 되돌리기(`Ctrl+Z`) 한 번으로 이전 배치로 돌아갈 수 있습니다.
- 위치(`x`, `z`)나 종류(`typeId`)가 없는 항목은 건너뜁니다. 치수, 색, 이름이 없거나 범위를 벗어나면 가구 목록의 기본값과 편집 패널의 허용 범위로 맞춥니다.
- 라벨 메모가 있는 가구에는 `"note": "분해 후 이동"`이 붙습니다. 메모는 40자까지 읽고, 비어 있으면 넣지 않습니다.
- 예전 v1 파일(평면도 참조만 있는 배치 파일)과 localStorage에 저장된 형식(가구 배열만 있는 JSON)도 계속 가져올 수 있습니다.

## 평면도 데이터

프리셋 구조는 좌표를 직접 적지 않고 [web/src/plan/presets.ts](web/src/plan/presets.ts)의 `PresetSpec`(열·행 크기와 격자 칸)에서 `buildPresetPlan`으로 만듭니다. 그래서 경계를 드래그해 `columns`·`rows`가 바뀌면 방·벽·문·창·싱크대가 모두 다시 계산됩니다. 저장소에는 특정 집을 옮겨 적은 평면도 데이터를 넣지 않습니다.

평면도 형식은 [web/src/types.ts](web/src/types.ts)의 `FloorPlan`이 정의하고, 불러온 프로젝트 파일은 [web/src/plan/planFile.ts](web/src/plan/planFile.ts)의 `parseFloorPlan`이 검증합니다.

- 좌표는 cm 단위이고, x는 오른쪽, y는 종이 아래쪽입니다.
- `rooms`: 방 다각형과 바닥재. 외벽 안쪽/바깥쪽 판단에도 쓰므로 집 안 공간을 빠짐없이 덮어야 합니다.
- `walls`: 선분. `exterior: true`인 외벽은 안쪽 면이 선 위에 오도록 바깥으로 밀어 세우고, 내벽은 선 중심에 세웁니다. 모서리 연장은 자동으로 계산합니다.
- `openings`: 중심점(`at`)만 적으면 가장 가까운 벽에 붙습니다. `opensToward`와 `hinge`로 문이 열리는 방향을 정합니다.
- `fixtures`: 싱크대처럼 움직이지 않는 붙박이.
- `notes`: 구조를 해석하면서 가정한 내용. 화면의 "구조 해석 메모"에 그대로 나옵니다.

## 구조

```
web/src/
  plan/            프리셋 생성(presets), 경계 리사이즈(presetResize), 구조 손잡이(structureEditor),
                   평면도 해석(resolve), 2D 기하, 충돌·벽 붙임 계산, 3D 생성(벽 CSG)
  furniture/       가구 목록, 절차적 3D 모델, 카드 썸네일
  scene/           렌더러·카메라(viewer), 가구 레이어, 포인터·키보드 조작
  state/           배치 상태와 되돌리기 기록, 프로젝트 파일 형식(layoutFile v2)
  ui/              시작 화면·프리셋 선택기, 상단 막대, 가구 목록, 선택 가구 패널, 내보내기·가져오기
```
